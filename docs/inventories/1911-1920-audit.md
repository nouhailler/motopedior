# Audit préalable — 1911–1920

Audit effectué le 6 novembre 2026, avant toute insertion.

Le projet est une PWA React 19 / Vite 6 / Tailwind 4, avec Workbox et IndexedDB via idb. Les composants photo et le service worker sont séparés du domaine historique. `public/inventory.json` est le catalogue normalisé (schéma 2) ; `data/models.json` et les inventaires Commons alimentent les médias. Aucun changement de framework ni de version physique IndexedDB n’est nécessaire.

Le catalogue contient 52 véhicules et 40 constructeurs. Les origines, les références 005–011, les corrections Peugeot/De Dion, les lots 1890–1900 et 1901–1910 sont présents. Les identifiants sont stables, les données anciennes et les conflits sont conservés. Les variantes sont des véhicules reliés ; les générations peuvent être décrites par variante/édition et relations, sans table de génération autonome. Les marques appartiennent à un constructeur avec historique de transferts. Les sociétés historiques peuvent être précisées par fiche : une marque actuelle n’est pas automatiquement le fabricant historique.

Les six dates typées séparent conception, brevet, prototype, début/fin de production et commercialisation. `documented_construction` date un exemplaire sans prétendre connaître le premier prototype ; `presentation_date` ne remplace pas la construction. Les intervalles, approximations, inconnues et conflits sont représentables. Le filtre chronologique utilise les bornes de construction ; les statistiques documentées exigent des bornes contenues dans la période, une existence vérifiée et une preuve datée.

Les sources portent type, organisme/auteur, dates, URL, niveau A–D et champs confirmés. Les assertions au champ relient valeur et sources. Les contradictions ouvertes empêchent la revue globale vérifiée. Le contrôle automatique garantit la cohérence déclarée, pas l’authenticité des archives.

`operations.js` détecte les doublons par constructeur, noms normalisés/alias, dates, variantes et motorisation ; une ressemblance ne provoque aucune fusion. L’import JSON est atomique et idempotent ; CSV et JSON conservent extensions, relations et métadonnées. `seed-update.js` ajoute les nouvelles fiches avec sauvegarde, préserve les modifications locales et signale les collisions. Les dossiers incertains résident dans `research_batches`, hors des véhicules confirmés. Une archive du catalogue avant intégration permettra la comparaison et la restauration hors modifications locales.

Les fiches affichent déjà chronologie, sources, assertions, relations, conflits, confiance et caractéristiques nullables. Les filtres couvrent dates, constructeur, pays, propulsion, catégorie, usage, statut et précision. Manquent les filtres de cylindrée, architecture moteur et confiance, ainsi que des distributions par cylindres/année/confiance et le compteur militaire. Les détails mécaniques complémentaires peuvent être ajoutés comme extension nullable validée, sans modifier les anciennes fiches.

La suite couvre domaine, migration, stockage transactionnel, imports, fusion, photos/licences et lots historiques. Les tests du lot 1901–1910 figent encore le total global à 52 : ils seront rattachés à l’archive de cette livraison afin de rester des tests de non-régression. Aucun défaut historique antérieur n’est arbitré dans cette évolution. L’exhaustivité internationale et la disponibilité photographique ne sont pas acquises.
